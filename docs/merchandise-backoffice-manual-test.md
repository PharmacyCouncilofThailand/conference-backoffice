# รายการทดสอบมือ (Manual Test Checklist) — Merchandise Backoffice

เอกสารนี้ใช้ตรวจสอบการทำงานของระบบจัดการพรีออเดอร์ของที่ระลึก (Merchandise Backoffice) ร่วมกับ API และฐานข้อมูลทดสอบในเครื่อง

---

## 1. การเตรียมสภาพแวดล้อมและการรันระบบ

1. **รัน `conference-api` (พอร์ต 3002)**
   - ตั้งค่า `.env` ชี้ไปยังฐานข้อมูลทดสอบ (PostgreSQL) ที่รัน migration ของโมดูล Merchandise แล้ว
   - รันเซิร์ฟเวอร์ API บนพอร์ต `3002`

2. **รัน `conference-backoffice` (พอร์ต 3001)**
   - ตั้งค่า `NEXT_PUBLIC_API_URL=http://localhost:3002` ใน `.env.local`
   - รันคำสั่ง:
     ```bash
     npm run dev
     ```
   - เปิดเบราว์เซอร์ที่ `http://localhost:3001` และเข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ (`role === 'admin'`)

---

## 2. รายการทดสอบตามลำดับการทำงาน (Spec §9)

- [ ] **1. เข้าเมนู "ของที่ระลึก" และเลือกงานประชุม (Event)**
  - ตรวจสอบว่าเมนู "ของที่ระลึก" แสดงในแถบเมนูซ้ายสำหรับ `admin` เท่านั้น และเปลี่ยน Event ได้โดยค่า `?eventId=` คงอยู่ใน URL เมื่อสลับแท็บย่อย

- [ ] **2. ตั้งค่าร้านพรีออเดอร์ (`/merchandise/store`)**
  - เปิดรับพรีออเดอร์ กำหนดวันเวลาเปิด–ปิด (เวลาไทย `GMT+7`) กรอกข้อความกำหนดการผลิตและการจัดส่ง แล้วกดบันทึก
  - ตรวจสอบว่าสถานะร้านบนหน้าภาพรวม (`/merchandise`) อัปเดตตรงตามช่วงเวลาที่ตั้งไว้

- [ ] **3. Seed สินค้าร่างเริ่มต้น (เมื่อยังไม่มีสินค้าในงาน)**
  - ในหน้าภาพรวม (`/merchandise`) กดปุ่ม **"สร้างรายการสินค้าร่างเริ่มต้น (7 รายการ)"** ยืนยันในกล่องโต้ตอบ และตรวจสอบว่าสร้างสินค้าร่างครบและปุ่มหายไปหลังมีสินค้าแล้ว

- [ ] **4. จัดการหมวดสินค้า (`/merchandise/categories`) และแบนเนอร์ (`/merchandise/banners`)**
  - เพิ่มหมวดสินค้า แก้ไขชื่อ สลับแสดง/ซ่อน เลื่อนลำดับขึ้น/ลง แล้วกด **"บันทึกลำดับ"**
  - อัปโหลดรูปแบนเนอร์ (JPG/PNG/WebP ≤ 5 MB) ตั้งลิงก์ `https://...` สลับแสดง/ซ่อน และจัดลำดับ

- [ ] **5. เติมข้อมูลและเผยแพร่สินค้าเดี่ยว (`/merchandise/products/[productId]`)**
  - ทดสอบสินค้าเดี่ยวครบทั้ง 3 รูปแบบตัวเลือก:
    - [ ] **ไม่มีตัวเลือก** (มีเฉพาะราคาหลัก)
    - [ ] **มีเฉพาะไซซ์** (เพิ่มชิปไซซ์ เรียงลำดับ เปิดขาย/ตั้งราคาเฉพาะบางไซซ์)
    - [ ] **มีทั้งไซซ์และสี** (ตาราง Matrix ไซซ์ × สี)
  - อัปโหลดรูปสินค้าอย่างน้อย 1 รูป แล้วกดปุ่ม **"เผยแพร่"** ตรวจสอบว่าสถานะเปลี่ยนเป็นเผยแพร่แล้ว

- [ ] **6. เติมข้อมูลและเผยแพร่สินค้าชุด Bundle**
  - เพิ่มส่วนประกอบทั้งแบบ **"กำหนดตายตัว"** และ **"ให้ลูกค้าเลือก"** (ติ๊กตัวเลือกที่อนุญาต)
  - ตรวจสอบการแสดง **"ราคาซื้อแยกรวม"** เทียบกับราคาชุด บันทึกส่วนประกอบ และกด **"เผยแพร่"**

- [ ] **7. ทดสอบปิดการขายส่วนประกอบแล้วตรวจผลในหน้า "ดูตัวอย่าง" (`/merchandise/preview`)**
  - ปิดการขาย (`saleEnabled = false`) ของสินค้าเดี่ยวที่เป็นส่วนประกอบของ Bundle
  - เปิดหน้า `/merchandise/preview` ตรวจสอบว่าการ์ด Bundle แสดงป้าย **"ซื้อไม่ได้: ส่วนประกอบในชุดปิดการขายชั่วคราว"** และคลิกดูรายละเอียดใน Modal ได้ครบถ้วน

- [ ] **8. สั่งซื้อจากหน้าร้าน Pris2026 และตรวจสอบในรายการคำสั่งซื้อ (`/merchandise/orders`)**
  - สร้างคำสั่งซื้อจากหน้าร้าน Pris2026 (หรือผ่าน API ลูกค้า)
  - ตรวจสอบว่าออเดอร์แสดงในตาราง `/merchandise/orders` และค้นหา/กรองตามวันที่ สถานะชำระ และสถานะจัดส่งได้

- [ ] **9. แก้ไขออเดอร์ที่ยังไม่ชำระเงิน (`/merchandise/orders/[orderId]`)**
  - เมื่อออเดอร์มี QR ที่ยังใช้งานได้ (`qr_active`) หรือเพิ่งหมดอายุไม่ถึง 2 นาที (`verifying`) ปุ่ม **"แก้ไขคำสั่งซื้อ"** ต้องกดไม่ได้ (disabled) พร้อมข้อความอธิบาย
  - เมื่อไม่มี QR ที่กำลังใช้งาน กด **"แก้ไขคำสั่งซื้อ"** แก้ข้อมูลผู้รับและจำนวนสินค้า/เพิ่มรายการใหม่ พร้อมระบุเหตุผล แล้วบันทึก ตรวจสอบว่ารายการและยอดรวมอัปเดต และมีบันทึกใน Audit trail

- [ ] **10. ชำระเงินและตรวจสอบสถานะการชำระ**
  - ชำระเงินจริงหรือจำลองสถานะชำระสำเร็จในฐานข้อมูลทดสอบ / กดปุ่ม **"ตรวจสอบการชำระ"** บนหน้ารายละเอียดคำสั่งซื้อ
  - ตรวจสอบว่าสถานะเปลี่ยนเป็น **"ชำระแล้ว"** และแสดงประวัติ Payment attempts

- [ ] **11. แก้ไขออเดอร์ที่ชำระแล้ว**
  - เปิด Modal **"แก้ไขคำสั่งซื้อ"** บนออเดอร์ที่ชำระแล้ว
  - ตรวจสอบว่าปุ่มบันทึก disabled หากรอยอดรวมใหม่ไม่เท่ากับยอดรวมเดิม หรือยังไม่ได้ติ๊ก **"ติดต่อผู้ซื้อแล้ว"** และกรอก **"บันทึกการติดต่อ"**
  - ทดสอบเปลี่ยนไซซ์/รายการที่มีราคาเท่าเดิม กรอกบันทึกการติดต่อและเหตุผล แล้วบันทึกสำเร็จ

- [ ] **12. บันทึกการจัดส่งรายออเดอร์และแบบ Bulk (`/merchandise/shipping`)**
  - รายออเดอร์: กด **"บันทึกการจัดส่ง"** บนหน้ารายละเอียดคำสั่งซื้อที่ชำระแล้ว กรอกบริษัทขนส่งและ Tracking ID (ทดสอบเลขที่มี `0` นำหน้า เช่น `001234`) และทดสอบแก้ไขการจัดส่งซ้ำ (ต้องบังคับกรอกเหตุผล)
  - แบบ Bulk: เปิด `/merchandise/shipping` ทดสอบวางข้อมูลจาก Excel (คั่นด้วย Tab และ `,` มีบรรทัดหัวตาราง บรรทัดว่าง เลขออเดอร์ไม่พบ ข้อมูลไม่ครบ และเลขออเดอร์ซ้ำ) ทดสอบปุ่ม **"เติมบริษัทขนส่งในแถวที่ว่าง"** และกด **"บันทึกการจัดส่ง"**

- [ ] **13. ส่งอีเมลแจ้งเตือนซ้ำ (Resend Notification)**
  - สำหรับรายการอีเมลในหน้ารายละเอียดคำสั่งซื้อที่มีสถานะ `failed` หรือ `unknown` กดปุ่ม **"ส่งอีกครั้ง"** (กรณี `unknown` ต้องแสดงคำเตือนเรื่องอาจส่งซ้ำ) กรอกเหตุผลและยืนยัน

- [ ] **14. รายการรอตรวจสอบการชำระเงิน (`/merchandise/reviews`)**
  - ตรวจสอบรายการที่อยู่ในสถานะรอตรวจสอบ กดปุ่ม **"ปิดเรื่อง"** กรอกบันทึกผลการตรวจสอบและยืนยัน
  - ตรวจสอบว่ารายการย้ายไปอยู่ในแท็บ **"ปิดเรื่องแล้ว"** และตัวเลขแจ้งเตือนบนแท็บเมนูย่อยลดลงทันที

- [ ] **15. รายงานยอดผลิต (`/merchandise/production`) และดาวน์โหลดไฟล์ Excel ทั้ง 2 จุด**
  - เปิด `/merchandise/production` ตรวจสอบยอดขายแยก ยอดจาก Bundle และแถวรวมทั้งหมดท้ายตาราง
  - กดปุ่ม **"ดาวน์โหลด Excel"** ในหน้ายอดผลิต และปุ่ม **"ดาวน์โหลด Excel (ตามตัวกรอง)"** ในหน้ารายการคำสั่งซื้อ ตรวจสอบว่าเปิดไฟล์ `.xlsx` ได้และข้อมูลตรงกับหน้าจอ

## 3. การตรวจสอบการแสดงผลและพฤติกรรม UI เฉพาะจุด (Responsive & Review Focus)

- [ ] **ความกว้างหน้าจอ 375 px (มือถือ) และ 1440 px (เดสก์ท็อป)**
  - ตรวจสอบทุกหน้าภายใต้ `/merchandise/**` ที่ความกว้าง `375 px` และ `1440 px` ว่าไม่มีการเลื่อนแนวนอนทั้งหน้า (ตารางเลื่อนเฉพาะในกรอบ `overflow-x-auto`) และปุ่มหลักกดได้สะดวก (ความสูงอย่างน้อย `44 px`)

- [ ] **Version Conflict (`409 MERCH_VERSION_CONFLICT`) คงค่าที่กรอกไว้**
  - เปิดหน้าแก้ไขสินค้าตัวเดียวกัน (`/merchandise/products/[productId]`) ซ้อนกัน 2 แท็บ
  - บันทึกข้อมูลในแท็บที่ 1 ให้สำเร็จ จากนั้นแก้ไขข้อมูลในแท็บที่ 2 แล้วกดบันทึก
  - ตรวจสอบว่าแท็บที่ 2 แสดงข้อความแจ้งเตือนภาษาไทยว่าข้อมูลถูกแก้ไขโดยผู้ใช้อื่น โดยที่ข้อความที่ผู้ใช้เพิ่งพิมพ์ในฟอร์มแท็บที่ 2 **ไม่ถูกล้างทิ้ง** และมีปุ่มให้กดโหลดข้อมูลล่าสุด

- [ ] **การกดปุ่มบันทึกซ้ำเร็วๆ (Double-click Prevention)**
  - ทดสอบดับเบิลคลิกปุ่มสร้างสินค้า หมวด แบนเนอร์ หรือบันทึกการจัดส่งอย่างรวดเร็ว
  - ตรวจสอบว่าปุ่มเข้าสู่สถานะ `disabled` ทันทีขณะกำลังส่งข้อมูล และสร้างข้อมูลเพียง 1 รายการโดยไม่ส่งคำขอซ้ำ
